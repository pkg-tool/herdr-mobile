# Herdr для Android

Нативный **клиент** на Kotlin и Jetpack Compose / Material 3. Herdr и все
shell/agent-процессы работают на компьютере. Приложение не содержит сервер,
не устанавливает его и не меняет его исходники. Android 8.0 (API 26) и новее.

## Интерфейс

Все надписи приложения — на английском. Собственная светлая/тёмная палитра,
состояния агентов и правила оформления описаны в [THEME.md](THEME.md). Постоянная навигация на телефоне:
40 dp сверху и 48 dp снизу, без учёта системных панелей Android. Одна pane
занимает всю ширину; серверная раскладка не переключается в глобальный zoom.

- **Terminal** (иконка клавиатуры) или касание терминала открывает прямой IME.
  Enter выполняет команду; Back скрывает клавиатуру. Ctrl/Alt действуют на
  следующую клавишу. Произвольное сочетание — **Pane actions → Send key…**.
- **Message** есть только у агентов: отдельный многострочный черновик,
  отправка только кнопкой **Send**. При смене pane ввод закрывается,
  черновик остаётся в памяти соответствующего сервера/pane.
- Нижний список `name 1/N` и свайп по нему переключают panes.
  **Pane overview** показывает раскладку: касание открывает pane,
  удержание открывает её действия, разделитель перетаскивается пальцем.
- Вкладки выбираются рядом с заголовком; новая вкладка доступна в **Workspace
  actions → New tab**. Серверы и агенты — в боковой навигации.
- Палец прокручивает терминал; щипок меняет размер шрифта. Обычное касание
  не кликает удалённое приложение. Для этого явно включается **Touch mouse
  mode** в меню pane. Аппаратная мышь работает независимо.
- Открытие клавиатуры не меняет размеры серверных PTY: видимая область
  сдвигается к курсору. **Zoom / restore for everyone** — отдельное явное
  действие с предупреждением о других клиентах.


- Несколько сохраняемых SSH-профилей и одновременных независимых подключений.
- Пространства и агенты в выдвижной панели; на широком экране — постоянная
  боковая панель. Группы репозиториев можно сворачивать.
- Создание, переименование, закрытие и изменение
  порядка пространств и вкладок. Отдельное подтверждение закрытия группы.
- Панели справа/снизу, выбор, перенос, обмен местами, масштабирование,
  изменение пропорций жестом или ползунком. Экспорт/импорт JSON-раскладки.
- Список агентов с состояниями и приоритетом ожидающих ответа; поиск при большом списке. Запуск и переименование.
- Создание, открытие и удаление Git worktree. Доверие репозиторию задаётся явно.
- Серверные команды, плагины, их действия/панели/журналы и интеграции.
- Потоковый цветной терминал: нативный Canvas рисует семантические ячейки,
  курсор, popup и RGB/RGBA/PNG-изображения. Навигация приложения — Compose,
  а не изображение настольного TUI.
- Экранная и аппаратная клавиатуры, IME, спецклавиши, произвольные сочетания
  Ctrl/Alt/Shift/Super, вставка текста, мышь и touch-прокрутка.
- Многострочное сообщение агенту с явной отправкой; shell управляется прямым вводом.
- Серверный поиск по всей доступной истории, переходы между совпадениями,
  страницы истории, выделение текста Android и копирование строки/совпадения.
- Отправка PNG/JPEG/GIF/WebP с телефона, ссылки с подтверждением, буфер обмена,
  уведомления серверов и переход к нужной панели.
- Системная/светлая/тёмная тема, размер шрифта, настройки уведомлений.

## Подключение

На компьютере должны быть доступны SSH и **уже запущенная** сессия Herdr.
Нужен сервер с endpoint generation 1 и командами `remote-client-bridge` и
`remote-api-bridge`. Проверенная версия: `0.9.5-local.clipboard1` из соседнего
checkout `../herdr`.

В приложении нажмите **+ Server** и укажите:

1. Название профиля, DNS-имя/IP и SSH-порт.
2. SSH-пользователя и имя сессии Herdr (`default` по умолчанию).
3. Путь к Herdr — `.local/bin/herdr` от домашнего каталога SSH-пользователя
   или абсолютный путь. `~` не разворачивается.
4. SHA256-отпечаток ключа SSH-сервера из доверенного источника. Допускается
   вставить всю строку вывода `ssh-keygen`.

На самом компьютере отпечаток можно получить командой:

```sh
ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub -E sha256
```

Нажмите **Connect**. Доступны пароль, импорт приватного ключа и вставка
PEM/OpenSSH-ключа, включая ключи с passphrase. Указанный host key проверяется
до аутентификации. Команды удалённого запуска рассчитаны на POSIX shell
(Linux/macOS); HTTP-прокси не нужен.

## Поведение подключений

Endpoint передаёт snapshot и кадры по постоянному SSH exec-каналу. Методы,
не опубликованные в endpoint, отправляются через отдельные API exec-каналы
того же SSH-соединения. Клиент не запускает настольный `TerminalHello`.

Выбор пространства/вкладки хранится на стороне клиентского endpoint.
**Размеры PTY общие на сервере:** активный телефон может изменить размеры
терминалов, видимых другим клиентам. Перенос панели меняет общую топологию.

Профили и настройки сохраняются в DataStore. Пароль по умолчанию используется
только для входа, ссылка фоновой задачи очищается после SSH-аутентификации.
Приватные ключи и черновики не сохраняются. Поворот экрана сохраняет текущую ViewModel;
после завершения процесса Android нужно подключиться снова. Постоянного
фонового сервиса нет: приложение не обещает получать уведомления, когда
Android остановил его процесс. Серверные процессы при этом продолжают работу.

При уходе приложения в фон поток кадров деактивируется. Состояния подключённых
серверов продолжают обновляться, пока процесс жив. Heartbeat обнаруживает
потерю соединения. Мутации и ввод никогда не повторяются автоматически;
после неоднозначной ошибки интерфейс сохраняет черновик и требует сначала
проверить результат отправки.

Графический кэш ограничен 64 МиБ; слишком большие/повреждённые изображения
показывают предупреждение с возможностью запросить новый кадр. Clipboard image
ограничен 16 МиБ. Пустой или недоступный серверный метод возвращает ошибку,
а не имитируется локально.

## Сохранённый пароль и биометрия

В диалоге Connect включите **Save password for biometric reconnect**, введите
пароль и подтвердите системный запрос биометрии. На диск записывается только
AES-256-GCM шифротекст, и только после успешной SSH-аутентификации. Ключ
создаётся отдельно для каждого профиля в Android Keystore, не экспортируется
и требует биометрию для каждой операции. Файл находится в noBackupFilesDir.

При следующем входе **Connect with biometrics** расшифровывает пароль только
для новой SSH-аутентификации. Поддерживаются системные Class 3 biometrics
(отпечаток, а на подходящих устройствах также лицо); PIN не заменяет биометрию
в этом сценарии. При отмене, lockout или недоступности сенсора остаётся ручной
вход. Фоновых запросов и автоматических повторных попыток SSH нет.

**Forget saved password** уничтожает ключ и файл. Изменение любого поля
подключения, кроме названия, и удаление профиля также удаляют секрет.
После изменения биометрии сохранённый ключ может стать недоступен: потребуется
повторно ввести и сохранить пароль. Активную SSH-сессию обычный lock/unlock
сам по себе не завершает. После обрыва или перезапуска приложения нужен новый
вход с биометрией. Поворот/уход в фон во время запроса отменяет операцию.

Диалог учётных данных защищён от скриншотов. Это не защищает от скомпрометированной
ОС, клавиатуры или отладчика после расшифровки; текущий APK — debug-сборка.
Неизменяемые String и временные копии JVM нельзя гарантированно стереть из RAM.

## Сборка и установка

Нужны JDK 17+, Android SDK 36 и Build Tools 36.0.0.

```sh
export ANDROID_HOME=/path/to/android-sdk
./gradlew :app:testDebugUnitTest :app:lintDebug :app:assembleDebug
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

Gradle Wrapper включён. Первая сборка скачивает зависимости из Google Maven,
Maven Central и Gradle distributions. APK debug подписывается стандартным
локальным debug-ключом; публикация в магазине и release-подпись не настроены.

## Проверка

Проверено 29 октября 2026: сборка APK, 36 JVM-тест и все 5 Android-сценариев
на эмуляторе API 36 прошли. Lint: 0 ошибок; предупреждения о версиях
зависимостей и необязательные рекомендации KTX. Live-сценарии использовали
настоящий Herdr по SSH.
Claude выполнил read-only ревью; подтверждённые ошибки исправлены.
На физический Pixel 10 установлен клиент, проверена доступность SSH через Tailscale.
Биометрическое подтверждение владельцем на Pixel требует отдельной ручной проверки.

Установочный APK: `dist/herdr-android-debug.apk`; скриншот: `dist/mobile-ui.png`.
Отчёт Android: `dist/android-tests.txt`.

- JVM-тесты: JSON/API, SSH pinning, параметры операций, layout, bincode framing,
  семантический ввод и применение surface patches.
- `LiveServerTest`: реальные SSH и две изолированные сессии Herdr, перекрывающиеся
  ID панелей, потоковые кадры, ввод, изоляция выбора двух клиентов, неверный host key.
- `MobileUiTest`: production Activity/Compose/ViewModel, создание вкладки и split,
  перетаскивание разделителя в overview, ширина выбранной pane, стабильность PTY
  при IME, переключение серверов и пересоздание Activity.
- `HistoryUiTest`: поиск глубже 500 строк, next/previous, реальный clipboard,
  возврат из истории к прямому IME, Enter, передача PNG с проверкой SHA-256 на сервере.
- `TouchInteractionTest`: пальцевой свайп, выбор панели, перетаскивание разделителя
  и отмена жеста без мыши и аппаратной клавиатуры.
- `TerminalGraphicsTest`: реальные Android Canvas/BitmapFactory, RGB/RGBA/PNG,
  сохранение ассетов между кадрами и сброс при смене server boot.

Live-тесты запускаются только с явно переданными параметрами **тестовых**
SSH/Herdr-сессий. Пример приведён в `validation.sh`; файл приватного ключа
передаётся исключительно в приватный каталог debug-приложения и удаляется
скриптом после запуска. На рабочих сессиях эти тесты не запускайте.

Контракт реализован по `../herdr/src/protocol/{wire,endpoint}.rs`,
`src/server/headless/client_views.rs` и `src/api/schema`. Сервер не изменён.

Проверка биометрии (30 октября 2026): `SavedPasswordTest` использует настоящий
Android Keystore и BiometricPrompt на отдельном эмуляторе API 36 с тестовым
отпечатком. Проверяет запрет encrypt/decrypt без авторизации, отмену с немедленной
повторной попыткой, сохранение/чтение, AAD привязку к серверу, повреждение
шифротекста, уничтожение ключа и отклонение позднего сохранения после Forget.
Запускается явно с `-e biometricTest true`; fingerprint touch подаётся через
консоль тестового эмулятора. Отчёт: `dist/biometric-tests.txt`.

Отчёт о подготовке публикации: [FDROID-READINESS.md](FDROID-READINESS.md).
